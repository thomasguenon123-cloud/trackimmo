## Findings

### FND-001 — Le cashflow des cartes SCI agrège du prévisionnel pur

- **Sévérité** : 🟠 HAUT · **Type** : JS / calcul
- **Localisation** : `app.js:8429`, dans `renderAdministration()`

```js
const cashflow = biensSCI.reduce((sum,b) => sum + computeCF(b), 0);
```

C'est **le défaut corrigé sur « Mes biens » le 03/08/2026**, resté en Administration. La règle
posée alors — *« toute agrégation passe par `cfDisplayData()`, jamais `computeCF()` seul »* — a
été appliquée à `renderBiens` et oubliée ici.

Deux conséquences, toutes deux vérifiables sur les données de Thomas :
- un bien **acquis avec des loyers encaissés** est compté en prévisionnel, alors que la fiche,
  les cartes et le Module financier affichent son réel ;
- une **fiche incomplète** (sans loyer estimé) fait retrancher ses charges d'un loyer nul et
  sort un gros négatif — c'est précisément ce que `cfDisplayData` neutralise.

**Fix** : `sum + (cfDisplayData(b).value || 0)`, et écarter les fiches dont `value` est `null`.
**Action** : AUTO · **Risque si ignoré** : chiffre faux sur l'écran qui sert à juger une société.

### FND-002 — Deux définitions de l'impayé : le badge dit « Occupé » sur un loyer impayé

- **Sévérité** : 🟠 HAUT · **Type** : JS / calcul
- **Localisation** : `app.js:7882` (`mfStatutOccupation`) et `app.js:6304` (`renderMfSuivi`)

```js
&& (l.statut === 'Impayé' || l.statut === 'En retard')
```

Ces deux tests cherchent les statuts `'Impayé'` et `'En retard'`. Or **l'application n'écrit
jamais ces valeurs automatiquement** : `bdGenererLoyers` et le pointage créent toutes leurs
lignes en `'En attente'` (lignes 1676, 6637, 6681, 6723, 8294). `'Impayé'` et `'En retard'` ne
sont posables **qu'à la main**, par la fenêtre d'encaissement.

**Preuve sur la base de Thomas** : les 19 lignes de `loyers_mensuels` ne portent que deux
statuts, `'Payé'` et `'En attente'`. Février 2026 est échu et non soldé.

Conséquences :
- `mfStatutOccupation` ne détecte jamais l'impayé → le badge affiche **« Occupé »** alors que
  la matrice, juste à côté, affiche février en rouge. **C'est visible sur la capture du
  05/08/2026** ;
- le compteur `impayes` du suivi mensuel reste **toujours à zéro**.

**Fix** : faire dépendre l'impayé de l'échéance et non du libellé, via `sfLoyerEtat(...) === 'ko'`
— la fonction créée le 05/08 pour la matrice, qui applique déjà la règle de l'agenda (un loyer
dû le 5 n'est en retard que le 6).
**Action** : AUTO · **Risque si ignoré** : un impayé passe inaperçu ; c'est l'information la
plus importante d'un écran de gestion locative.

### FND-003 — 22 données utilisateur interpolées sans échappement dans du HTML

- **Sévérité** : 🟠 HAUT · **Type** : JS / intégrité d'affichage
- **Localisation** : `app.js` lignes 1863, 2294, 2301, 2569, 4211, 6540, 6568, 7211, 8002,
  8436, 8667, 8838, 8944, 9117, 10278 et 7 autres

```js
<div class="kc-title">${b.titre}</div>          // ligne 2294
<div class="sci-card-name">${s.nom_sci}</div>   // ligne 8436
<div class="mfs-charge-cat">${c.categorie}</div>// ligne 6568
```

L'audit du 03/08 avait traité **les attributs** (70 champs de formulaire) ; le **contenu texte**
est resté. Un bien intitulé `Maison <b>test</b>` s'affiche en gras ; un titre contenant `<`
tronque le rendu.

Le risque d'exécution est limité — les données sont cloisonnées par RLS, chacun ne voit que les
siennes — mais il n'est pas nul : **les contacts et les SCI sont partageables**, et une chaîne
recopiée depuis une annonce peut contenir du balisage sans intention malveillante.

**Fix** : `${esc(...)}` sur chacune. `esc()` existe déjà et est utilisée partout ailleurs.
**Action** : AUTO · **Risque si ignoré** : affichage cassé sur données réelles, injection HTML
dans les objets partagés.

### FND-004 — Résidu TrackImmo côté serveur : `TRACKIMMO_SSO_RESTREINT`

- **Sévérité** : 🟡 MOYEN · **Type** : DETTE / renommage
- **Localisation** : trigger `trg_block_external_signup` sur `auth.users`, fonction
  `public.block_external_provider_signup` ; côté client `app.js:247` et `app.js:301`

La fonction lève une exception dont le message contient `TRACKIMMO_SSO_RESTREINT`, que le
client reconnaît pour afficher un refus en français. C'est **le dernier TrackImmo vivant** de la
plateforme : tous les autres sont des commentaires historiques.

**Fix** : renommer en `STONEFOLIO_SSO_RESTREINT` — **migration DDL, donc à la charge de Thomas**
(le MCP est en lecture seule). Le client doit accepter **les deux** chaînes le temps de la
bascule, sinon un refus d'inscription s'afficherait en erreur brute pendant l'intervalle.
**Action** : CONFIRM

  `admin-invite-user`, `news-proxy`).
